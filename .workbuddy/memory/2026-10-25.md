## 踩坑记录（重要）

### 1. 全局 `.scss` 里不能写 `:deep()`

`:deep()` 由 `@vitejs/plugin-vue` 在编译 SFC 的 `<style scoped>` 时重写；独立 `.scss` 文件
不经过该处理，产物保留字面量 `:deep(...)` → 无效选择器 → **整条规则被浏览器丢弃**。
我第一版把 `.search-form { :deep(.el-form-item){...} }` 写进 `style/element-plus.scss`，
构建成功但规则不生效。校验方法：`grep ':deep(' dist/static/css/index-*.css` 应为 0。

### 2. pydantic-settings 的 `env_file` 参数名要带下划线 —— 导致全站配置从未加载

`service/src/config/settings.py:220` 原为 `Settings(env_file=...)`，应为 **`_env_file=`**。
写成 `env_file` 会被当作未知字段，在 `extra="ignore"` 下**静默丢弃**，
`.env` / `.env.development` / `.env.production` / `.env.testing` 从未生效，全站跑在模型默认值上。

连锁后果（本项目真实发生）：
- `REDIS_URL` 取默认 `redis://localhost:6379/0`。Windows 下 `localhost` 优先解析到 IPv6 `::1`，
  本机 Redis 3.2.100 只监听 IPv4 → 异步连接必超时 → **缓存永久降级** → 单请求被拖到 3s 量级。
- 开发环境 `CORS_ORIGINS` 默认**不含 8848**（前端 dev 源）。

**这修正了此前 MEMORY.md 里"E2E 随机假失败 = Redis 未就绪"的判断：真正的根因是这个配置 bug。**
已修复（`env_file` → `_env_file`），后端 pytest 2171 全部通过。

⚠️ 副作用：`_ensure_production_secrets()` 这个 fail-fast 校验此前从未生效。修复后若
`.env.production` 仍含 `your-` 前缀占位密钥，生产启动会**按设计直接抛错**。部署前需确认密钥。

### 3. 脚本改模板时注意引号嵌套

`:style="{ minHeight: "var(--x)" }"` 在 Vue 模板里是无效属性（属性本身由 `"` 定界）。
内层必须用单引号：`:style="{ minHeight: 'var(--x)' }"`。

### 4. 图标名必须在本地图标集中真实存在，否则整页白屏

`~icons/ri/button-line?raw` 在 `@iconify-json/ri` 中不存在时，unplugin-icons 报
`Pre-transform error: Icon xxx not found` → `layout/index.vue` 动态导入失败 →
**整个应用白屏**，且 typecheck / eslint / stylelint / build **全部通过**，只有运行时炸。
排障：看 `web/vite_out.txt` 里的 `Pre-transform error`；用
`require("@iconify-json/ri/icons.json").icons[name]` 校验。

### 5. 改了 sys_menumeta 后菜单图标不变 → Redis 缓存

缓存已启用，菜单树被 Redis 缓存，直接改库不生效，需要 `redis-cli -n 0 FLUSHDB`。

### pnpm 12 的配置迁移坑（重要，会静默失效 + 让 install 非幂等）

- pnpm 12 **不再读 `package.json` 的 `pnpm` 字段**（`allowedDeprecatedVersions`、
  `onlyBuiltDependencies` 静默失效，启动时有 WARN）。新家在 `pnpm-workspace.yaml`：
  `allowedDeprecatedVersions:` / `allowBuilds:` / `shellEmulator` / `shamefullyHoist` /
  `enablePrePostScripts` / `strictPeerDependencies` / `minimumReleaseAge`。
  上游已把 `.npmrc` 删掉、`package.json` 无 `pnpm` 字段——照抄即可。
- **新增带原生构建脚本的依赖会让 `pnpm install` exit 1**：`code-inspector-plugin` v2 拖入
  `node-pty`，pnpm 自动往 `allowBuilds` 写占位 `node-pty: set this to true or false` 并报
  `ERR_PNPM_IGNORED_BUILDS`。必须显式写 `node-pty: false`。
- **install 中断会把 node_modules 打烂**：`.pnpm` 被清空、72 个顶层符号链接悬空，
  后续 install 报 `ERR_PNPM_PACKAGE_MANAGER_REMOVE_MODULES_DIR ... 拒绝访问`。
  修法：`CODEBUDDY_SAFE_DELETE_ENABLED=0 pnpm install --force`（1m42s 重建）。
  判据：`find node_modules -maxdepth 1 -type l ! -exec test -e {} \; -print | wc -l` > 0 即悬空。

## 全量测试与修复：定位「pytest 抹除 dev.db 列」根因（本轮提交）

上一节「schema drift 复发」只修了症状，本轮用决定性实验定位到**真根因**并根治。

### 决定性实验

```text
BEFORE: username 列存在 = True
2171 passed in 605.20s
AFTER:  username 列存在 = False（alembic_version 仍为 head c4d5e6f7a8b9）
```

### 根因：三缺陷叠加

1. **`alembic/env.py` 用裸 `Settings()`**（非 `get_settings()`）。裸构造器 `model_config`
   只认 `.env`，而项目**没有 `.env` 文件**；且 testing 的库覆盖
   （`_ENV_OVERRIDES["testing"]["DATABASE_URL"]=.../test.db`）**只在 `get_settings()` 里应用**。
   实测 `APP_ENV=testing` 下裸 `Settings().DATABASE_URL = sqlite+aiosqlite:///./sql/dev.db`
   （模型默认值），而 `get_settings()` 正确给出 test.db。
2. **`tests/unit/test_alembic_cli.py` 子进程真实执行 alembic 且未隔离库**：pytest 的
   `APP_ENV=testing` 被子进程继承 → `upgrade head`（空转）+ `downgrade -1`
   （执行 `c4d5e6f7a8b9.downgrade()` 删列）+ `stamp head`（版本戳推回 head 不补 Schema）
   → 「版本戳超前、结构落后」。迁移 upgrade 虽幂等，但版本已在 head 不会再执行 → **每次跑 pytest 复发**。
3. `scripts/cli.py` 的 `initdb` 已委托 `run_migrate()`，同样受缺陷 1 影响。

### 修复（3 处 + 1 处 mypy 清理）

| 文件 | 改动 |
|---|---|
| `service/alembic/env.py` | 裸 `Settings()` → `get_settings()`；顺带补 `do_run_migrations(connection: Connection)` 标注 |
| `service/tests/unit/test_alembic_cli.py` | hermetic 化：`tmp_path` + `DATABASE_URL` 环境变量指向临时库；rollback 测试改 `migrate → rollback -1 → migrate` 闭环；mypy 3 错→0 错 |
| `service/sql/dev.db` | `alembic stamp a3b5c7d9e1f2` → `upgrade head` → 全表结构核对（16 表零漂移，91 行日志保留） |

**为什么测试里选 `APP_ENV=development`**：testing 的 DATABASE_URL 覆盖以构造参数传入，
优先级高于环境变量，会盖掉临时地址；development 覆盖字典为空，环境变量即可生效。

### 验证

| 项 | 结果 |
|---|---|
| CLI 测试单跑 | 3/3，dev.db BEFORE/AFTER 一致 |
| 全量 pytest | **2171 passed in 493.68s**（较修复前 605.20s 快 ~2min），dev.db 前后一致 |
| E2E | **51/51（2.4m）** |
| mypy | env.py / test_alembic_cli.py 均清零 |

### 沉淀的防护约定

- **裸 `Settings()` 是 footgun**：需要按 APP_ENV 解析配置的调用方一律走 `get_settings()`。
  判别：`APP_ENV=testing python -c "from src.config.settings import Settings, get_settings; print(Settings().DATABASE_URL, get_settings().DATABASE_URL)"`，两者必须一致。
- **子进程测试必须隔离数据库**：凡 subprocess 触发 alembic/cli，一律 `tmp_path` + `DATABASE_URL`
  指向临时文件；APP_ENV 选覆盖字典为空的 development。
- **pydantic-settings 优先级**：构造参数 > 环境变量 > dotenv > 模型默认值。
