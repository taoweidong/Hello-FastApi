## 字典管理页补齐「新增字典」主入口

**根因（git 历史定位）**：`a48fc0f` 初版在 PureTableBar `#buttons` 有「新增字典」主按钮；
`985f2cf` 改造为「左树 + 右表」双栏时，把它替换成两个细分入口：左树底部「新增子典」（错别字）
→ `openAddDictType`，右侧工具条「新增字典详情」→ `openAddDictDetail`。
此后页面再无文案为「新增字典」的主按钮，且错别字一直遗留。

**修复**（`web/src/views/system/dictionary/index.vue`）：
- 右侧 `#buttons` 首位补实心 `type="primary"` 主按钮「新增字典」，绑定 `openAddDictType`
  （**不能绑 `openAddDictDetail`**：后者要求已选中字典类型，否则只弹 warning 不进流程）。
- 左侧「新增子典」→「新增类型」；右侧「新增字典详情」→「新增子项」（与右键菜单文案统一）。
  这样全页**恰好一个** accessible name 含「新增字典」的按钮，避免 `getByRole` 子串匹配歧义。
- 权限全部沿用 `v-auth="'dictionary:add'"`，不附加任何 `v-if` 显示条件。
  已核对链路：dev.db 的 `dictionary:add` 权限节点挂在 Dictionary 菜单下 → 后端
  `build_route_tree` 写进 `meta.auths` → `hasAuth` 放行；admin 为超管，按钮不会被误隐藏。
- `form.vue` / `hook.tsx` 注释里的错别字「新增子典」一并清理；对话框标题
  （「新增字典类型」「新增字典详情」）保持不变，E2E 依赖它们。

**E2E 同步**：`crud-dictionary.spec.ts` 按钮定位文案同步，并新增主按钮的
`toHaveCount(1)` / `toBeVisible` / `el-button--primary` / 点击进流程断言。

## 顺带止血：`crud-monitor-server.spec.ts`

全量 E2E 曾 1 红：`getByRole("button", { name: "刷新" })` 子串同时命中「刷新」与「刷新日志」
→ strict mode violation。由最近 `bb41750`（日志目录远程浏览）新增「刷新日志」按钮引起，
与字典页改动无关。改为 `{ name: "刷新", exact: true }`。

> 通用教训：Playwright `getByRole` 的 `name` 默认**子串匹配**；页面新增带前缀的按钮
> （刷新/刷新日志、新增字典/新增字典详情）会让旧用例突然 strict violation。
> 定位按钮时要么 `exact: true`，要么保证文案唯一。

`git restore -- <这三个文件>`，否则会污染提交。
