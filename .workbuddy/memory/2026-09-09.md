## 全流程优化与功能性验证（E2E 闭环）

### 修复的缺陷（4 个 E2E 失败用例全部闭环）

1. **E2E hash 路由导航失效**（`web/e2e/helpers.ts`）
   `gotoModule` 用 `page.goto(path)`，但 vue-router 是 `createWebHashHistory`，非 hash 跳转会被忽略并回落 `/welcome`。改为 `page.goto(\`/#${path}\`)`。

2. **部门新增表单提交读到过期数据**（`web/src/views/system/dept/`）
   - `hook.tsx` 的 `beforeSure` 原读 `options.props.formInline`（弹窗创建时的初始快照），导致提交空值。
   - 修复：`form.vue` 新增并暴露 `getFormData()`，`beforeSure` 改读实时数据。
   - payload 对齐后端 `DepartmentCreateDTO`：补 `modeType`/`autoBind`，删除钩子中不存在的 `principal`/`phone`/`email`，`code` 传字符串空值、`parentId` 传 null。

3. **部门创建返回 500（真因）**
   - `sys_departments.code` 为 `NOT NULL` + `UNIQUE`；部门表单**没有**「编码」输入项，前端提交 `code: ""`，与 dev.db 中调试残留的空 code 行冲突 → SQLite UNIQUE 冲突 → 后端 500 → 弹窗不关闭。
   - 修复：hook 在无 code 时生成唯一编码 `DEPT_${Date.now()}_${rand}`（持久修复）；并删除 `dev.db` 中残留的 `e2e_deptdbg_*` 测试行（已确认无外键引用）。
   - 补充：`dept/utils/types.ts` 的 `FormItemProps` 增加可选 `modeType`/`autoBind`，修复由此引入的 vue-tsc TS2339 报错。

4. **smoke-account 断言过严**（`web/e2e/smoke-account.spec.ts`）
   `/account-settings` 是 `remaining.ts` 全屏路由，既不渲染 `.el-table` 也没有 `.app-main`，`gotoModule` 的「表格或空状态」轮询必然超时。改用 `utils/helpers` 的 `gotoPage`。

### 踩坑补充

- `pnpm run lint` 带 `--fix`，会顺带改写大量源文件（含 stylelint 的 CSS 属性排序修复），使 60+ 文件被标记修改；但其中仅约 17 个有实质 diff，其余为 CRLF/LF 行尾差异（git 归一化后 `git diff --name-only` 为空）。提交前应先用 `git diff --stat` 甄别，只提交实质改动。
- 推送报 `could not read Username`：全局 gitconfig 只配了 HTTP(S) 代理、未配 `credential.helper`。执行 `git config credential.helper manager` 后即可用 Windows 凭据管理器完成推送。
