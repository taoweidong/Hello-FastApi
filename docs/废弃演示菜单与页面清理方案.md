# 废弃演示菜单与页面清理方案

> 目标：删除/废弃项目中「演示性质、业务不使用」的菜单与页面，保持导航干净。
> 状态：**待评审**（破坏性操作，确认范围后执行）。

## 一、盘点结果

「演示/未使用」的菜单与页面来自两处来源，需分别处理：

### 1）后端 DB 菜单 —— 权限演示目录（`service/src/domain/rbac_defaults.py` 的 `DEFAULT_MENUS`）

开发库 `service/sql/dev.db` 已 seed，实测共 **7 行**：

| name | title | menu_type | path | 说明 |
|---|---|---|---|---|
| `Permission` | 权限管理 | 0 目录 | `/permission` | 演示目录 |
| `PermissionPage` | 页面权限 | 1 页面 | `/permission/page/index` | 演示页 |
| `PermissionButton` | 按钮权限 | 1 页面 | `/permission/button/index` | 演示页 |
| `PermissionPerms` | 按钮权限组件 | 1 页面 | `/permission/button/perms` | 演示页 |
| `permission:btn:add` | — | 2 权限 | `/permission/button` | 演示按钮权限码 |
| `permission:btn:edit` | — | 2 权限 | `/permission/button` | 演示按钮权限码 |
| `permission:btn:delete` | — | 2 权限 | `/permission/button` | 演示按钮权限码 |

同时 `USER_MENU_NAMES` 里也引用了 `Permission / PermissionPage / PermissionButton / PermissionPerms` 四个名字。

### 2）前端静态菜单（`import.meta.glob("./modules/**/*.ts")` 自动注册，非 DB）

| 模块文件 | 路由 | 页面目录 | 说明 |
|---|---|---|---|
| `web/src/router/modules/about.ts` | `/about` → `/about/index` | `web/src/views/about/` | pure-admin 演示「关于」页 |
| `web/src/router/modules/guide.ts` | `/guide` → `/guide/index` | `web/src/views/guide/` | pure-admin 演示「引导」页 |

### 3）孤立页面（既无路由也无菜单引用，纯遗留资源）

| 目录 | 引用情况 | 后端接口 |
|---|---|---|
| `web/src/views/result/{success,fail,columns.tsx}` | 全仓无路由/无组件引用（仅 `enums.ts` 有 `result` rank 常量） | 无 |
| `web/src/views/monitor/logs/system/` | 无菜单、无路由引用 | **有**（`POST /api/system/system-logs`、`/system-logs-detail`） |

### 4）明确保留（不动）

- `/welcome` 首页、`/login`、`/error/403`、`/error/500`、`/account-settings`、`/empty`（remaining 里的无 layout 示例）
- 后端 `system-logs` 接口本身保留（即使暂时不删 `logs/system` 页面）

> 注：`enums.ts` 里 `about/guide/permission/result` 等 rank 常量是 pure-admin 模板残留；`locales/{zh-CN,en}.yaml` 里 `pureAbout/pureGuide/purePermission*` 键同理。删页面后这些键会变成未使用，可顺手清理（保留也无害，不影响运行）。

## 二、影响面

- **导航**：删除后侧边栏不再出现「权限管理」（含 3 个子页）、「关于」、「引导」。
- **权限**：`admin` 角色对这些菜单的 `sys_userrole_menu` 关联会随菜单删除级联清除；`USER_MENU_NAMES` 同步更新。
- **E2E**：`web/e2e/utils/helpers.ts` 的 `SMOKE_PAGES` 含 5 条相关注册（`/permission/page/index`、`/permission/button/index`、`/permission/button/perms`、`/about/index`、`/guide/index`）；`web/e2e/crud-permission.spec.ts` 整文件覆盖这三个演示页 → 必须同步删除/更新，否则 E2E 失败。
- **DB 结构**：`sys_menus.parent_id` 自引用外键；`sys_userrole_menu.menu_id` 外键带 `ON DELETE CASCADE` 且已 `PRAGMA foreign_keys=ON`；但 `sys_menumeta` **不会**被级联删（Menu 引用 Meta，非反向）。因此清理顺序必须是：**先删菜单 → 再删 meta**（关联表由级联自动清）。
- **测试**：`service/tests/unit/test_domain_rbac_defaults.py` 只断言 `len>0` 与类型，**未硬编码 Permission 名称**，删除安全。

## 三、执行步骤（确认后）

1. **后端 seed 定义**：`rbac_defaults.py` 删除 `Permission` 系列 7 条 + `USER_MENU_NAMES` 里的 4 个引用。
2. **开发库一次性清理**：按 `name IN (...)` 删除 `sys_userrole_menu`（级联，可省）+ `sys_menus` + 对应 `sys_menumeta`；以脚本/Alembic 迁移形式提供（幂等；`seedrbac` 对已存在按 name 跳过，删定义后不会重建）。
3. **前端删除**：`router/modules/about.ts`、`guide.ts`；`views/about/`、`views/guide/`、`views/permission/`（如纳入范围，另含 `views/result/`、`views/monitor/logs/system/`）。
4. **可选清理**：`enums.ts` 未用 rank 常量、`locales` 未用 i18n 键、`utils/sso.ts` 注释里指向 `/permission/page/index` 的示例链接。
5. **E2E 同步**：更新 `SMOKE_PAGES`；删除 `crud-permission.spec.ts`（及可能引用这些页的其它断言）。
6. **验证**：`pnpm typecheck && pnpm lint && pnpm build`；重启后端；E2E 全量串行复跑至全绿。

## 四、待确认：删除范围

- **方案 A（推荐，最小语义）**：删除最典型的演示项 —— 后端「权限管理」7 条菜单 + 前端「关于」「引导」两页。
- **方案 B（彻底）**：在 A 基础上，**额外**删除孤立遗留资源 —— `views/result/`、`views/monitor/logs/system/`（注意后者保留后端接口）。
