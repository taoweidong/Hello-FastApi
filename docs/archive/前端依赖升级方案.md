# 前端依赖升级方案（从上游开源库更新所有组件）

> 基线：`web/` HEAD = `300e629`（前端全量优化已完成并推送）
> 上游参照：`pure-admin/vue-pure-admin` `master`（同为 v7.0.0，fork 源头）
> 工具链：Node v22.22.2 / pnpm 12.4.1

## 1. 目标与范围

把 `web/` 的所有第三方组件库升级到上游最新可用版本，同时**不破坏本地定制**
（`tokens.scss` 设计令牌、`offlineIconNames.ts` 离线图标注册、全局 `.search-form` /
`.main-content` 规则、`hooks.ts` 离线/在线图标分流等）。

原则：**能升尽升，跨大版本以上游已实际采用的版本为准，无上游参照的跨大版本一律不升。**

## 2. 升级全景（`pnpm outdated` 实测）

共 57 个包有新版本，其中运行时 16 个、开发期 41 个。

## 6. 实际执行结果（2026-10-25）

### 6.1 升级引入的两处类型错误及修复

升级后 `vue-tsc` 报 2 个错误（基线为 0，已 A/B 对照证实由升级引入）：

| 文件 | 错误 | 根因 | 修复 |
|---|---|---|---|
| `src/views/system/user/utils/hook.tsx` | `Module "@zxcvbn-ts/core" has no exported member 'zxcvbn'` | v4 移除了顶层便捷导出 `zxcvbn()`，只保留 `ZxcvbnFactory` | 改为 `new ZxcvbnFactory()` + `.check(pwd).score`，与上游 `master` 同文件写法完全一致 |
| `src/components/ReIcon/src/iconifyIconOffline.ts` | `Argument of type 'object' is not assignable to parameter of type 'string'` | `props: { icon: { default: null } }` 缺显式 `type`，Vue 新版本的 prop 推断 + `typeof` 收窄后不再兼容 `addIcon(name: string, ...)` | 补 `type: [String, Object, Function] as PropType<any>`，同样与上游一致 |

### 6.2 pnpm 配置迁移（升级的连带修正）

`pnpm install` 幂等重跑报 `ERR_PNPM_IGNORED_BUILDS`（新依赖 `node-pty` 来自 `code-inspector-plugin` v2），
且 pnpm 12 已不再读取 `package.json` 的 `pnpm` 字段
（`allowedDeprecatedVersions` / `onlyBuiltDependencies` 静默失效）。
按上游做法一次性迁到 `pnpm-workspace.yaml`：

- `package.json` 删除整个 `pnpm` 字段；
- 删除 `web/.npmrc`（`shell-emulator` / `shamefully-hoist` / `enable-pre-post-scripts` / `strict-peer-dependencies` 四项迁入 yaml）；
- `pnpm-workspace.yaml` 补齐 `allowedDeprecatedVersions` 与 `allowBuilds`（含 `node-pty: false`）。

结果：`pnpm install` 幂等（exit 0、无任何 WARN）、`node_modules` 无悬空符号链接。

> 注：迁移过程中因 `node-pty` 未授权导致一次 install 中断，`node_modules/.pnpm` 被清空、
> 72 个顶层符号链接悬空；用 `pnpm install --force` 完整重建后恢复。

### 6.3 prettier 3.9 的连带格式化

`eslint --fix`（经 eslint-plugin-prettier）按 prettier 3.9 新规则折叠了 4 处短联合类型，
涉及 `ReDialog/type.ts`、`ReDrawer/type.ts`、`utils/message.ts`、`views/system/menu/utils/hook.tsx`，纯格式、无行为变化。

### 6.5 E2E 首跑 1 失败的处置

首跑 50/51：`/empty` 冒烟捕获到 `/api/system/login-logs` 500。
根因是 **`service/sql/dev.db` 的 schema drift**（`sys_userloginlog` 缺 `username` 列，
而 `alembic_version` 已 stamp 到 `c4d5e6f7a8b9`——"版本戳超前、结构落后"），
与本次前端升级无关（后端零改动）。按既定 SOP 处置：

1. 备份 `sql/dev.db` → `sql/dev.db.bak-drift-20261025-091846`；
2. `alembic stamp a3b5c7d9e1f2` → `alembic upgrade head`（该迁移本身幂等，回退版本戳后才会真正执行）；
3. 全表结构核对（SQLModel metadata ↔ 实际库）确认无其它 drift；
4. 重启后端重跑 E2E → 51/51。
