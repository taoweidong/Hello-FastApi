## 3. 低危问题（择机修，P2）

**后端**：`get_token_service` 每请求重建 Settings；`_build_tree` 递归 O(n²)；JWT 用 python-jose（维护停滞，可迁 PyJWT）；`fastapi[standard]` 瘦身；`[tool.uv]` 镜像硬编码；限流 storage_uri import 时固化。

**前端**：`vxe-table` 全局注册零使用（移除）；`vite-plugin-compression` 迁 compression2；`user.ts` `SET_XXX` Vuex 风格命名；路由层类型洼地（`router/utils.ts` 的 `handRank(routeInfo: any)` 等）；测试 markers 不完整（后端 31 个 unit 文件无标记）。

## 5. 风险与回滚

- **B2（refresh 黑名单）**：影响所有已登录用户的 refresh 行为，需确认 Redis 黑名单 key 的 TTL 与 refresh token 过期一致，避免新会话被误伤。
- **B5（lifespan 改 Alembic）**：生产首次切换时 create_all 与迁移的 schema 差异需要一次性 head 生成收敛，建议先在 dev 环境演练。
- **F1（strict 收紧）**：一次性开 full strict 会暴露数百错误，**必须分三步**，每步独立提交。
- **F2**：拦截器重构需覆盖「刷新成功重放」「刷新失败登出」「并发 401」三条路径的 E2E。
- 回滚：每批独立提交，出问题 `git revert` 单批即可。
