# 前端样式优化方案（2026-11）

> 目标：在**保持现有整体格式**（主色、主题、布局范式、组件结构不变）的前提下，
> 优化布局与表单展示，提升体验、美观度与流畅度。

## 一、基线与原则

前端已有三层样式体系，本次**不新建体系、只在其上收敛**：

| 层 | 文件 | 职责 |
|---|---|---|
| 设计令牌 | `src/style/tokens.scss` | 间距 / 动效时长与缓动 / 圆角阴影 / 层级 / 断点 |
| 主题 | `src/style/theme.scss` | 7 套主题的菜单配色变量 |
| 深色适配 | `src/style/dark.scss` | Element Plus 组件与布局层的深色覆盖 |
| 组件覆盖 | `src/style/element-plus.scss` | Element Plus 全局微调 + 布局一致性收敛 |

四条原则：

1. **不推翻格式**——不动主色、主题、布局范式（树+表 / 分栏）、组件库选型。
2. **同一语义单一来源**——同一件事只留一处写法，改一处即全局生效。
3. **隐性失效优先修**——看起来做了、实际没生效的（截断失效、焦点环被抹、深色硬编码）比"锦上添花"优先。
4. **可验证**——每批改动都能被 lint / typecheck / build / E2E 覆盖。

### 首轮 E2E 回归（14 红）复盘

首轮全量 E2E 出现 14 个失败，全部为同一根因：给顶栏全局搜索入口补的
`aria-label="全局搜索"` 与全站 15 处 `getByRole("button", { name: "搜索" })` 冲突——
**Playwright 的 `getByRole` name 是子串匹配**，于是同时命中「全局搜索」入口与页面搜索按钮，
报 strict mode violation。

修法：把该入口的 `aria-label` 改为不含「搜索」二字的 `全局检索`（语义不变，且不与任何按钮文案冲突），
避免改动 13 个 spec 的定位代码。这是本项目第二次踩到「子串匹配」坑（上次是「刷新」vs「刷新日志」）。

**约定：新增 `aria-label` 前，先用 `grep -rh 'getByRole("button"' web/e2e` 列出所有按名称定位的按钮，
确认新标签不会成为既有名称的子串。**
